1. Sumário Executivo

O Apiário Tech é uma plataforma IoT de monitorização apícola que combina sensores instalados no apiário, recolha local através de microcontrolador ESP32 e uma aplicação web para transformar leituras técnicas em informação compreensível e útil para a gestão de colmeias.

2. Contexto e Problema

A avaliação do estado de uma colmeia depende habitualmente de visitas presenciais ao apiário e de observações realizadas durante as inspeções. Entre visitas, alterações de temperatura, humidade, peso ou funcionamento do equipamento podem passar despercebidas.

Problemas identificados

  • Registos manuais dispersos e difíceis de analisar;
  • Impossibilidade de detetar anomalias entre visitas;
  • Ausência de histórico estruturado de leituras e intervenções;
  • Não existe ligação permanente à Internet no apiário;
  • Necessidade de autonomia energética e de armazenamento local.

3. Visão do Produto

O Apiário Tech permitirá ao utilizador responder rapidamente a perguntas como:

  • Qual é o estado atual de cada colmeia?
  • Como evoluíram a temperatura, a humidade e o peso?
  • Existem leituras anómalas que justificam atenção?
  • Que inspeções, alimentações ou tratamentos foram realizados?
  • O dispositivo está a recolher dados de forma regular?

Objetivos principais

  • Centralizar a informação relativa aos apiários e colmeias;
  • Recolher e conservar telemetria com data e hora fiáveis;
  • Apresentar o estado atual e o histórico de forma clara;
  • Apoiar o acompanhamento através de alertas básicos;
  • Manter registo cronológico das intervenções;
  • Funcionar durante falhas de Internet e interrupções de energia;
  • Permitir evolução gradual sem reconstruir a solução.

Objetivos de longo prazo

  • Transmissão automática via 4G, LoRa ou Wi-Fi;
  • Alertas avançados baseados em padrões históricos;
  • Deteção e acompanhamento da Vespa velutina;
  • Modelos de inteligência artificial validados.

Fluxo de dados

  1. Sensores recolhem dados ambientais e do ninho;
  2. ESP32 valida, formata e grava em CSV no microSD;
  3. Utilizador importa o ficheiro CSV para a plataforma;
  4. Backend valida, deduplica e persiste na base de dados;
  5. Frontend apresenta dashboard, histórico e alertas.

6. Modelo de Dados

O schema da base de dados inclui 8 modelos interligados:

ModeloResponsabilidadeRelações
UserUtilizadores e autenticação (email, password hash, role)1:N → Apiary
ApiaryApiários (nome, localização, coordenadas GPS)N:1 → User; 1:N → Hive
HiveColmeias (nome, posição, estado ativo)N:1 → Apiary; 1:N → Device, Reading, Alert, Intervention
DeviceDispositivos ESP32 (ID único, modelo, firmware)N:1 → Hive; 1:N → Reading
TelemetryReadingLeituras de telemetria (10 métricas + validação)N:1 → Device, Hive
AlertRuleRegras de alerta (métrica, operador, limiar)1:N → Alert
AlertAlertas gerados (mensagem, valor, reconhecimento)N:1 → AlertRule, Hive
InterventionIntervenções (inspeção, alimentação, tratamento, colheita)N:1 → Hive
Regra de deduplicação: A combinação (device_id, timestamp) é única. Importações repetidas do mesmo ficheiro não criam duplicados.

CódigoSignificado
OKTodos os sensores funcionaram normalmente
BME280_FAILBME280 não respondeu
BME280_STALELeitura não variou desde o ciclo anterior

Valor sentinela: -127.00 indica falha de sensor. O backend rejeita valores sentinelas como medições válidas e marca a leitura com o estado de falha correspondente.

13. Segurança

  • Autenticação: JWT com expiração configurável;
  • Palavras-passe: Hash com bcrypt (10 rounds);
  • Validação: Todos os inputs validados com Zod antes de processar;
  • Segredos: Nunca no código-fonte; variáveis de ambiente (.env);
  • CORS: Configurado para origens autorizadas;
  • Dados: Leituras não são eliminadas sem rastreabilidade;
  • Autorização: Cada utilizador acede apenas aos seus apiários.
